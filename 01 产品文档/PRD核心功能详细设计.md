## 4.1 功能一：AI纠纷智能分析（P0）

### 4.1.1 功能背景

用户遇到租房纠纷时，通常只能通过搜索引擎查询相关信息，但由于缺少法律知识，无法准确判断：

- 自身是否存在权益风险
- 房东行为是否合理
- 当前需要补充哪些信息
- 下一步应该采取什么措施

因此，通过AI大模型理解用户描述，并结合租房领域知识库，对用户问题进行结构化分析。

### 4.1.2 用户目标

> 用户希望：输入自己的租房问题后，系统能够理解我的情况，并告诉我当前问题、风险以及下一步怎么办。

### 4.1.3 功能流程

```
用户输入纠纷描述
        ↓
  AI识别纠纷类型
        ↓
   抽取关键信息
        ↓
  判断信息完整度
        ↓
   缺少信息？
    │        │
    ↓ 是      ↓ 否
 AI主动追问   继续分析
    │        │
    └──→←────┘
        ↓
  调用租房知识库
        ↓
  生成分析报告
```

### 4.1.4 页面设计

#### 页面1：创建纠纷案件页

| 模块 | 字段 |
|------|------|
| 纠纷类型 | 押金纠纷（V1.0；提前退租、维修责任、合同问题为后续版本） |
| 租赁时间 | 开始日期、结束日期 |
| 涉及金额 | 金额输入 |
| 问题描述 | 文本输入框 |
| 上传资料 | 合同、图片、聊天记录 |

**用户输入示例：**

```
我和房东签了一年合同，现在到期退房，但是房东说墙面有损坏，
不退3000元押金。
```

#### AI处理逻辑

**Step1：意图识别**

```json
{
  "问题类型": "押金纠纷",
  "置信度": 0.93
}
```

**Step2：信息抽取**

```json
{
  "角色": "租客/房东",
  "金额": "3000元",
  "争议": "押金返还",
  "原因": "墙面损坏"
}
```

**Step3：缺失信息判断**

AI判断缺少的信息：

- 是否有入住照片
- 是否有退房验收记录
- 房东是否提供维修证明

**AI追问示例：**

```
AI：为了更准确分析您的情况，请补充以下信息：

1. 合同是否已经到期？
2. 房东是否提供维修费用证明？
3. 入住时是否拍摄过房屋照片？
```

### 4.1.5 AI分析报告生成

**报告结构：**

#### ① 纠纷概览

```
用户租赁合同到期后退房，房东以墙面损坏为由拒绝返还3000元押金。
```

#### ② 当前风险评估

```
风险等级：中风险

原因：
1. 房东存在扣款理由
2. 但目前缺少维修费用证明
3. 用户已有聊天记录
```

#### ③ 关键争议点

| 争议点 | 说明 |
|--------|------|
| 墙面损坏责任 | 是否属于正常损耗 |
| 维修费用 | 是否真实合理 |
| 押金扣除 | 是否符合合同约定 |

#### ④ 建议补充证据

优先级：最高

需要补充：

- 租赁合同
- 支付记录
- 入住照片
- 退房视频

#### ⑤ 下一步建议

1. 要求房东提供维修凭证
2. 保存双方沟通记录
3. 尝试协商退款

### 4.1.6 异常处理

| 情况 | 处理方式 |
|------|---------|
| 用户描述过短 | 引导补充信息 |
| AI无法判断 | 提示咨询专业人士 |
| 知识库无匹配内容 | 返回通用建议并标记低可信度 |

## 4.2 功能二：AI证据智能管理（P0）

### 4.2.1 功能背景

租房纠纷中，用户通常拥有大量资料：

- 合同
- 图片
- 聊天记录
- 支付截图

但不知道：

- 哪些重要
- 如何分类
- 是否缺少关键证据

### 4.2.2 用户目标

> 用户希望：上传材料后，AI帮我整理证据，并告诉我还缺什么。

### 4.2.3 功能流程

```
用户上传文件
    ↓
  文件解析
    ↓
 AI识别类型
    ↓
 提取关键信息
    ↓
 生成证据目录
    ↓
  关联案件
```

### 4.2.4 页面设计

#### 证据管理页面

```
案件：押金纠纷

证据列表：

  ✅ 租赁合同.pdf
     类型：合同文件

  ✅ 微信聊天.png
     类型：沟通记录

  ✅ 转账记录.jpg
     类型：付款证明

  ⚠ 缺少：
     退房验收记录
```

### 4.2.5 AI能力设计

#### 文档识别

**合同识别：**

```
提取：
  - 租期
  - 押金金额
  - 违约责任
```

**聊天截图识别：**

```
提取：
  - 时间
  - 双方身份
  - 关键争议
```

#### 证据评分

```
证据名称：房屋照片
重要程度：★★★★★
作用：证明入住及退房状态
```

### 4.2.6 Bad Case 优化

| 问题 | 优化方案 |
|------|---------|
| AI误判聊天截图 | 增加图片OCR能力 |
| 分类不准确 | 增加人工确认标签环节 |

## 4.3 功能三：AI行动指南生成（P0，V1.0黄金路径）

### 4.3.1 功能背景

用户知道问题之后，仍然不知道下一步应该怎么办。

### 4.3.2 用户目标

> 获得：简单、明确、可执行的处理步骤。

### 4.3.3 功能流程

```
AI读取案件分析结果
    ↓
读取已上传证据
    ↓
检索知识库（投诉/法律途径）
    ↓
生成行动方案
    ↓
输出话术模板
```

### 4.3.4 页面设计

#### 行动方案页面

```
当前阶段：协商阶段

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

第一步：整理证据

需要：
  ✅ 合同
  ✅ 支付记录
  ✅ 聊天记录

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

第二步：联系房东

AI生成话术：
"您好，关于押金返还问题，根据双方签订的租赁合同，
目前房屋已完成交接，请提供相关维修依据，谢谢。"

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

第三步：投诉渠道

根据情况选择：
  - 平台投诉
  - 调解
  - 法律咨询
```

### 4.3.5 AI能力设计

**Prompt输入：**

```
用户情况 + 证据情况 + 知识库结果
```

**Prompt输出：**

```
行动步骤 + 沟通模板 + 注意事项
```

## 4.4 功能四：租房合同风险检测（后续版本，P1）

### 4.4.1 功能背景

用户签订租房合同前，无法快速发现风险条款。

### 4.4.2 功能流程

```
上传合同
    ↓
 PDF解析
    ↓
 条款切分
    ↓
 风险识别
    ↓
生成合同报告
```

### 4.4.3 检测内容

#### 押金条款

```
风险：未约定返还时间
等级：中风险
建议：增加"7日内返还"条款
```

#### 维修责任

```
风险：维修责任完全由租客承担
等级：高风险
建议：按法律规定区分自然损耗和人为损坏
```

### 4.4.4 异常处理

| 情况 | 处理方式 |
|------|---------|
| 合同格式不支持 | 提示粘贴纯文本 |
| 合同内容过短 | 提示上传完整合同 |
| 无法识别条款 | 标记"待人工确认" |

## 4.6 AI Agent 工作流图

> 以下是租安AI核心功能"AI纠纷智能分析"的完整Agent工作流，展示从用户输入到报告生成的全链路AI处理过程。

### 4.6.1 主工作流：AI纠纷智能分析全链路

> **完整度阈值说明：** V1.0暂以信息完整度≥80%作为进入正式分析的门槛。80%是待评测校准的产品假设，不是已经验证的最优阈值；后续将结合离线测试集和用户反馈调整要素权重与阈值。

```
用户输入纠纷描述
        │
        ▼
┌─────────────────────────────────────────────────┐
│  Agent节点1：意图识别（LLM）                      │
│                                                   │
│  输入：用户原始描述                                │
│  处理：LLM判断纠纷类型                            │
│  输出：                                           │
│    {                                              │
│      "问题类型": "押金纠纷",                       │
│      "置信度": 0.93                               │
│    }                                              │
│                                                   │
│  置信度 < 0.6？                                   │
│    → 是：返回Agent节点1重新识别（附追问）          │
│    → 否：继续                                     │
└─────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────┐
│  Agent节点2：信息抽取（LLM + 结构化输出）          │
│                                                   │
│  输入：用户原始描述 + 纠纷类型                     │
│  处理：LLM从非结构化文本中提取关键字段             │
│  输出：                                           │
│    {                                              │
│      "角色": "租客",                              │
│      "金额": "3000元",                            │
│      "争议": "押金返还",                           │
│      "原因": "墙面损坏",                           │
│      "合同状态": "已到期",                         │
│      "房东态度": "拒绝退还"                        │
│    }                                              │
└─────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────┐
│  Agent节点3：信息完整度判断（规则 + LLM）          │
│                                                   │
│  输入：已抽取的结构化信息                          │
│  处理：对比"押金纠纷标准要素清单"                  │
│                                                   │
│  标准要素清单：                                    │
│    □ 合同是否到期                                  │
│    □ 押金金额                                      │
│    □ 房东扣款理由                                  │
│    □ 是否有入住照片                                │
│    □ 是否有退房验收记录                            │
│    □ 房东是否提供维修证明                          │
│    □ 是否有沟通记录                                │
│                                                   │
│  输出：                                           │
│    {                                              │
│      "完整度": "60%（规则计算示例）",             │
│      "缺失字段": [                                │
│        "入住照片",                                 │
│        "退房验收记录",                              │
│        "维修证明"                                  │
│      ],                                           │
│      "需要追问": true                             │
│    }                                              │
```

### 4.6.4 Agent工作流设计要点（面试可讲）

| 设计要点 | 说明 | 为什么这样设计 |
|---------|------|---------------|
| 多节点串联而非单次LLM调用 | 意图识别→信息抽取→完整度判断→检索→生成→校验，6个节点 | 单次调用容易幻觉；拆分后每步可独立验证、独立优化 |
| 信息完整度判断+追问循环 | 判断缺失字段→追问→补充→重新抽取 | 模拟律师咨询过程，信息越完整分析越准 |
| RAG检索放在报告生成前 | 先检索法条，再让LLM基于检索结果生成报告 | LLM只做"整合"不做"回忆"，从源头防幻觉 |
| 幻觉校验作为独立节点 | 报告生成后单独校验法条真实性 | 最后一道防线，即使前面出错也能拦住 |
| 证据管理用OCR+LLM组合 | 先OCR提取文字，再LLM提取关键信息 | OCR负责"看到"，LLM负责"看懂" |
| 行动指南读取案件上下文 | 从案件报告+证据列表读取，不是重新分析 | 避免重复计算，保证和建议与分析报告一致 |
