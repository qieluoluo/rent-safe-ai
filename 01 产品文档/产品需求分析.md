# 租安 AI —— 租房纠纷智能分析与证据管理平台


## 一、项目背景分析

### 1.1 行业背景

随着城市流动人口增加，租房已经成为大量年轻群体的重要居住方式。

在租赁过程中，用户经常会遇到：

- 房东拒绝退还押金
- 提前退租产生纠纷
- 房屋维修责任划分不清
- 合同条款存在风险
- 租赁双方沟通记录混乱等问题

但普通租房用户通常存在以下困难：

- 缺少法律知识，无法判断自身权益
- 不清楚需要收集哪些有效证据
- 不知道如何与房东进行有效沟通
- 面对合同、聊天记录、图片等非结构化信息，整理成本高

### 1.2 传统解决方式及其问题

传统解决方式主要依赖：

- 自行搜索网络信息
- 咨询律师
- 向相关机构投诉

但这些方式存在明显不足：

| 方式 | 问题 |
|------|------|
| 搜索引擎 | 信息零散，需要用户自行判断 |
| 咨询律师 | 成本较高，不适合所有小额纠纷 |
| 投诉平台 | 需要用户提前整理完整材料 |
| 传统法律APP | 偏法律知识展示，缺少个性化分析 |

### 1.3 为什么需要AI

传统工具只能"提供信息"，不能"理解用户情况"。

用户真正需要的是：**有人能听懂我的具体情况，帮我理清事实、整理证据、告诉我下一步该怎么做。**

这正是AI大模型擅长的事情：

- 理解自然语言描述（用户大白话 → 结构化事实）
- 多轮追问澄清（像律师咨询一样，逐步补充关键信息）
- 知识库检索增强（RAG：从法律知识库中找到相关法条）
- 个性化方案生成（基于用户具体情况，生成专属处理方案）

因此，需要一个能够理解用户具体情况，并辅助用户整理信息、分析风险、制定处理方案的AI产品。

### 2.1 目标用户

**核心用户：年轻租房群体**

用户画像：

| 属性 | 描述 |
|------|------|
| 年龄 | 18-35岁 |
| 身份 | 大学毕业生、职场新人、城市流动人口 |
| 租房经验 | 较少 |
| 法律知识 | 有限 |
| 技术接受度 | 较高 |

### 2.2 典型场景

> 小李第一次在外地租房，退租后房东以墙面损坏为由扣除全部押金，但不知道如何判断是否合理，也不知道需要准备什么证据。

### 2.3 用户特征总结

| 特征 | 描述 | 对产品的影响 |
|------|------|-------------|
| 法律知识薄弱 | 不懂法条，看不懂合同条款 | 分析结果必须用大白话，不能堆法律术语 |
| 问题频率低 | 不是天天遇到，偶尔一次 | 即问即用，不需要重度学习 |
| 付费意愿低 | 觉得小事不值得花钱 | 产品要免费或极低成本 |
| 情绪化 | 遇到纠纷容易焦虑、愤怒 | 回答要冷静客观，安抚情绪 |
| 行动力弱 | 知道有问题，但不知道第一步干什么 | 必须给出具体可操作的行动路径 |
| 信息整理能力弱 | 合同、聊天记录、照片散落各处 | 需要AI帮助整理、分类、提取关键信息 |

## 三、用户痛点分析

### 痛点1：不知道自己的情况是否合理

**用户心声：**

> "房东扣我押金合法吗？"

**实际情况：** 用户缺少对以下信息的判断能力——

- 合同约定了什么
- 损坏情况是否属于正常损耗
- 双方责任如何划分
- 自己手里有什么证据

**用户需要的：** 根据我的具体情况分析风险，而不是简单告诉我法律条文。

### 痛点2：证据分散，难以整理

租房纠纷相关资料通常包括：

- 租赁合同 PDF
- 支付记录
- 微信聊天截图
- 入住照片
- 退房视频
- 维修报价单

**目前：** 用户需要自己整理。

**问题：**

- 不知道哪些重要
- 不知道如何分类
- 不知道缺少什么

### 痛点3：不知道下一步应该做什么

**用户通常处于焦虑状态：**

> "我现在应该找房东沟通？投诉？还是起诉？"

**需要清晰行动路径：**

```
收集证据
    ↓
协商沟通
    ↓
平台投诉
    ↓
调解/法律途径
```

## 五、产品定位

### 5.1 产品定位

**面向个人租房用户的AI纠纷辅助决策平台，通过大模型、知识库检索和智能分析技术，帮助用户快速理解纠纷情况、整理关键证据，并生成可执行的处理方案。**

### 5.2 产品边界

**产品不提供：**

- 律师代理服务
- 法院判决预测
- 保证胜诉结果
- 替代专业法律意见

**产品提供：**

- 信息整理
- 风险提示
- 法律知识辅助
- 处理路径建议

### 功能一：AI纠纷智能分析（P0）

**用户需求：**

> 用户希望：输入自己的问题后，AI能够理解情况，并告诉我重点在哪里。

**功能描述：**

通过大语言模型理解用户描述，结合租房领域知识库，对纠纷进行分析。

**功能流程：**

```
用户描述问题
    ↓
意图识别
    ↓
信息抽取
    ↓
判断信息完整度
    ↓
缺失信息追问
    ↓
知识库检索
    ↓
生成分析结果
```

**输出内容：**

**1. 纠纷类型**

```
类型：押金返还纠纷
```

**2. 事实摘要**

AI自动整理：

```
用户租期已结束，房东以墙面损坏为理由拒绝退还3000元押金。
```

**3. 风险分析**

```
当前风险等级：中风险

原因：
1. 房东提出损坏主张
2. 暂未提供维修证明
3. 用户缺少验收记录
```

**4. 信息缺口**

```
还需要补充：
□ 租赁合同
□ 房屋入住照片
□ 退房视频
□ 房东维修凭证
```

### AI模块1：意图识别

V1.0识别押金纠纷；其他类型识别为暂不支持并进入后续版本需求池：

- 押金纠纷（V1.0支持）
- 退租纠纷（后续版本）
- 维修纠纷（后续版本）
- 合同风险（后续版本）

### AI模块2：RAG知识增强

知识库结构：

```
租房知识库
├── 民法典租赁相关条款
├── 房屋租赁合同示范文本
├── 常见租房纠纷案例
├── 证据收集指南
└── 投诉处理流程
```

### AI模块3：信息完整度判断

判断用户描述是否缺少关键事实，并主动追问。

**V1.0阈值假设：** 暂以信息完整度≥80%作为进入正式分析的门槛。80%是待评测校准的产品假设，不是已经验证的最优阈值；后续将结合离线测试集和用户反馈调整要素权重与阈值。

**例如：**

```
用户：房东扣押金。

AI：需要继续询问——
    合同是否到期？
    房东扣款理由？
    是否有维修凭证？
```

| 指标 | 说明 |
|------|------|
| 问题分类准确率 | 是否识别正确纠纷类型 |
| 信息提取准确率 | 合同字段是否正确提取 |
| 引用准确率 | 法律依据是否匹配知识库 |
| 幻觉率 | 是否生成不存在的内容 |
| 建议可执行性 | 用户是否认可建议可操作 |

## 十一、产品价值总结

### 用户价值

降低普通用户处理租房纠纷的信息门槛。

### 产品价值

将复杂法律问题转化为：**可理解、可整理、可执行**的处理方案。

### AI价值

利用大模型能力完成：

- 非结构化信息理解（聊天记录、合同、照片 → 结构化事实）
- 多轮问题澄清（像律师咨询一样，逐步补充关键信息）
- 知识增强分析（RAG：从法律知识库检索相关法条，避免幻觉）
- 个性化建议生成（基于用户具体情况，生成专属处理方案）
