# 租安 AI — 3 分钟演示脚本

> **用途：** 面试/作品集现场演示  
> **前提：** 后端 `uvicorn` 运行在 8000 端口，前端 `npm run dev` 运行在 5173 端口

---

## 口述开场（30 秒）

「这是租安 AI，一个面向租客的押金纠纷辅助决策工具。V1 只做押金纠纷一个场景，目标不是替代律师，而是帮用户把事实、证据和行动串起来。当前 Demo 运行在**演示模式**，用的是规则 Mock 基线，不是真实大模型。」

---

## 演示步骤（2 分钟）

### Step 1：首页 — 说明能力边界（15 秒）

1. 打开 `http://localhost:5173`
2. 指出右上角 **「演示模式 · 规则 Mock 基线」** 标签
3. 简要说明三类状态：已实现 / 演示模式 / 规划中

**话术：** 「这里明确标注了当前是演示模式，避免把 Mock 能力包装成大模型。」

### Step 2：新建案件 — 填入样例（30 秒）

1. 点击「开始分析」
2. 点击「填入演示样例」
3. 展示预填内容：3000 元押金、合同到期、房东以墙面损坏扣 2000 元
4. 点击「创建并分析」

**话术：** 「用户只需要用自然语言描述情况，系统会自动抽取金额、扣款理由、租约状态等关键字段。」

### Step 3：分析报告 — 展示六步工作流（60 秒）

1. 等待分析完成（约 1-2 秒）
2. 展示顶部摘要：纠纷类型、风险等级、完整度得分
3. 向下滚动，依次指出：
   - **事实摘要**
   - **风险分析**
   - **法律依据**（带来源链接的引用 ID）
   - **证据缺口**
   - **行动建议**
4. 滚动到 **Agent 工作流轨迹**，展示 6 步节点及每步输出

**话术：** 「报告不是黑盒输出。每一步 Agent 的输入输出都落库，可以追溯分析过程。法律依据必须能追溯到具体条款，不能只写‘知识库显示’。」

### Step 4（可选）：API 文档 — 展示工程深度（15 秒）

1. 打开 `http://localhost:8000/docs`
2. 展示 `POST /api/cases/{case_id}/analysis` 接口

**话术：** 「后端是 FastAPI，五张表、统一响应结构，Mock 和真实 Provider 可以切换。」

---

## 收尾（30 秒）

「这个项目体现的是 AI 产品经理的完整链路：从问题定义、MVP 收敛、Agent 流程设计，到 Mock 基线、评测闭环和 Bad Case 迭代。当前 23 条合成用例上 Mock 全通过，但这是规则基线，下一步会接入真实模型并在同一测试集上对比。」

---

## 常见问题快速应答

| 问题 | 回答要点 |
|---|---|
| 用户研究是真的吗？ | 模拟研究，已标注，不能写进简历成果 |
| 真的做了 RAG 吗？ | 当前是关键词匹配 4 条内置文本，向量 RAG 是规划 |
| 为什么用 Mock？ | 确定性基线，先验证流程和评测管道，再对比真实模型 |
| 完整度怎么算？ | 核心字段门槛 + 权重得分，默认 80%，不是简单数非空字段 |
