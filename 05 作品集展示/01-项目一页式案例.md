## 项目概述

**租安 AI** 是面向普通租客的押金纠纷辅助决策工具：将自然语言描述和证据整理为事实摘要、风险提示、证据缺口和下一步行动建议。**不替代律师，不承诺法律结果。**

| 项 | 内容 |
|---|---|
| 角色 | AI 产品经理（个人项目） |
| 场景 | V1.0 仅覆盖**押金纠纷** |
| 用户 | 遇到押金被扣/不退的普通租客 |
| 价值主张 | 从「看不懂法条」到「知道缺什么、下一步做什么」 |

---

## 问题与假设

**用户痛点（基于模拟用户研究形成的待验证假设）：**

- 不知道自己的情况是否「站得住脚」
- 不清楚需要准备哪些证据、按什么顺序行动
- 通用法律问答无法串联「事实 → 证据 → 行动」

> 注：项目中的 6 人访谈、128 份问卷均为**模拟研究**，用于练习研究框架，不代表真实调研结论。

---

## MVP 与关键决策

| 决策 | 选择 | 原因 |
|---|---|---|
| 场景收敛 | 仅押金纠纷 | 金额明确、事实要素可标准化，适合验证端到端闭环 |
| AI 基线 | 规则 Mock 先行 | 确定性基线，先验证流程与评测管道，再接入真实模型 |
| 工作流 | 六步可观测节点 | 意图→抽取→完整度→检索→风险→报告，每步可追踪 |
| 完整度 | 核心字段门槛 + 权重得分，默认 80% | 避免「填字段凑数」，优先保证关键事实齐全 |

---

## AI 方案（设计 vs 实现）

```text
用户描述 → 意图识别 → 信息抽取 → 完整度评估 → 知识检索 → 风险评估 → 报告生成
```

| 能力 | 状态 | 说明 |
|---|---|---|
| 六步 Mock 工作流 | **演示模式** | mock-v1.2 规则基线，23 条合成用例全通过 |
| Agent 轨迹落库 | **已实现** | 每步写入 `ai_task`，前端可展示 |
| 前端黄金路径 | **已实现** | 描述 → 创建案件 → 分析 → 查看报告 |
| 向量 RAG / FAISS | **规划中** | 当前为 4 条内置文本关键词匹配 |
| 真实 LLM Provider | **规划中** | 代码骨架已有，尚无真实模型评测 |
| OCR 证据解析 | **规划中** | 当前仅支持文件上传与元数据 |

## 评测与迭代证据

- **Golden Set：** 23 条脱敏合成用例（`04 AI效果验证/测试案例/deposit-v1-synthetic.jsonl`）
- **基线结果：** mock-v1.2 在合成集上 scope/amount/lease_status/reason/completeness 均为 100%（**仅规则基线，非真实模型**）
- **Bad Case 闭环：** v1.1 → v1.2 修复 6 个失败用例，全量回归 0 失败
