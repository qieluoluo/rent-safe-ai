> 本文件用于面试复盘，不进入公开作品集。答案必须随项目真实进度更新。

## 二、核心知识点

### 1. 模拟研究数据如何使用

- 模拟数据只能用于提出假设、演练方法和帮助设计原型。
- 不能用模拟样本证明市场规模、频率、转化率或用户偏好。
- 对外应写“基于公开资料与模拟用户研究形成初步假设”。
- 后续真实研究需要保留招募标准、访谈提纲、脱敏记录、问卷原题、样本结构和计算口径。

### 2. MVP 不是功能最少，而是最小可验证闭环

租安 AI 的最小闭环不是“做一个聊天框”，而是：

```text
描述押金纠纷 -> 补齐关键事实 -> 上传或登记证据 -> 输出有依据的风险提示 -> 给出下一步行动 -> 收集反馈
```

若缺少证据与行动环节，就无法验证项目声称的差异化价值。

### 3. 需求优先级的四个判断维度

1. 用户价值：是否直接降低判断或行动成本。
2. 差异化：是否区别于通用法律问答。
3. 验证价值：能否验证核心假设。
4. 成本与风险：开发成本、模型成本、法律与隐私风险。

### 4. 产品指标分层

| 层级 | 示例指标 | 说明 |
|---|---|---|
| 获得价值前 | 案件创建完成率、关键问题补充率 | 判断流程是否过重 |
| 获得价值时 | 报告查看率、证据建议采纳率 | 判断输出是否被消费 |
| 行动结果 | 话术复制率、行动步骤完成率 | 判断是否真正推动行动 |
| 结果反馈 | 问题是否解决、结果回填率 | 判断长期真实价值 |
| 护栏 | 严重法律错误率、隐私投诉率 | 任何增长都不能突破的底线 |

## 三、项目面试问答

### Q1：为什么做租房纠纷，而不是通用法律 AI？

**回答框架：**

通用法律问答覆盖面广，但用户真正困难的是把自身事实、证据和行动联系起来。租房押金纠纷的事实要素、证据类型和处理阶段更容易标准化，适合先验证垂直场景的端到端辅助决策价值。项目并不试图替代律师，而是降低小额纠纷早期的信息整理和行动门槛。

### Q2：你的用户研究是真的吗？

**准确回答：**

当前版本的 6 人访谈、128 份问卷和人物画像都是模拟研究，用于练习研究框架并形成待验证假设，不是实际研究结论。项目已经统一标注其性质，因此不会将相关百分比写进简历成果。下一步真实验证会优先访谈有押金纠纷经历的租客，并保留可审计的研究材料。

### Q3：为什么 V1 只做押金纠纷？

**回答框架：**

押金纠纷有明确金额、强行动动机、较标准的事实字段和证据链，能同时验证案件梳理、证据管理和行动建议三项核心假设。维修与提前退租会引入更多责任归因和地域差异，放进 V1 会扩大评测和合规范围，反而难以把一个闭环做深。

### Q4：你的核心差异化是什么？

**回答框架：**

不是“用了大模型”，而是把通用问答延伸成证据与行动闭环：系统会判断缺失事实、整理证据及其证明目的、明确哪些结论有依据，并给出分阶段行动。这个差异化仍需通过真实竞品测试和用户任务实验验证，目前是产品假设而不是既成护城河。

### Q5：如何判断 MVP 成功？

**回答框架：**

先看流程能否完成，再看输出是否准确，最后看是否推动行动。核心包括案件创建完成率、必要问题补充率、报告查看率、建议采纳/话术复制率、严重错误率和结果回填率。AI 离线指标不能替代用户行为指标，二者需要共同达标。

### Q6：为什么行动指南是 V1 的一部分？

**回答框架：**

用户痛点不是“看不懂法条”本身，而是不知道下一步做什么。如果只生成分析报告，产品仍停留在信息提供。行动指南是完成价值闭环所必需的，但 V1 只提供分阶段建议和沟通草稿，不替用户自动投诉或做法律代理。

### Q7：产品最大的风险是什么？

**回答框架：**

一是错误法律信息导致错误行动，二是合同、聊天和付款记录泄露，三是用户把风险提示误解为律师结论。因此需要来源引用、低置信度升级、明确边界、最小采集、授权与删除机制，并把严重错误率作为硬性护栏。

### Q8：商业化怎么考虑？

**回答框架：**

当前阶段不先验证付费，而先验证用户是否愿意完成流程并采取行动。可能方向包括低价单次深度报告、证据材料包、专业律师转介，但都必须在真实需求、获客成本、推理成本和合规成本有数据后再判断，不能把律师导流预设为必然模式。

## 四、需要避免的表达

- 不说“调研发现 68% 用户遇到押金纠纷”，因为当前数据是模拟的。
- 不说“市场上完全没有竞品”，应说“初步案头研究中尚未发现完整覆盖该闭环的产品”。
- 不说“平台都站房东一边”，应使用可验证、客观的服务边界描述。
- 不把功能列表当成果；成果需要用户行为、质量或效率的真实变化。
