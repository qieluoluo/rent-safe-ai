## 二、核心知识点

### 1. 什么时候需要多节点，什么时候单次调用就够

多节点不是越多越高级。只有当任务存在可独立评测的中间状态、需要条件分支、需要确定性校验或不同节点的成本/模型选择不同时，拆分才有价值。租安 AI 可拆分是因为事实抽取、信息完整度、知识检索和报告生成有不同质量标准。最终仍需用端到端质量、延迟和成本证明拆分优于单次调用。

### 2. Mock、单次 LLM、工作流三类基线

| 基线 | 价值 | 局限 |
|---|---|---|
| 规则 Mock | 确定、便宜、方便验证产品流程 | 无真实语言理解能力 |
| 单次 LLM | 快速得到能力上限和常见失败 | 难定位中间错误、输出不稳定 |
| 分节点 LLM + 检索 | 可观测、可局部优化、引用可约束 | 调用多、延迟和成本更高 |

正确做法是保留三组，在同一测试集上比较，而不是预设复杂方案一定更好。

### 3. 法律 RAG 的最小数据契约

每个检索片段至少应有：

- 文档名称与条款号。
- 原文内容。
- 颁布/生效/失效时间。
- 发布机构与权威来源链接。
- 适用地域和主题标签。
- 文档版本或内容哈希。

生成结果中的法律依据必须能追溯到具体片段，不能只显示“知识库显示”。

### 4. 评测指标不能只看准确率

| 模块 | 推荐指标 |
|---|---|
| 意图识别 | Macro-F1、UNKNOWN 召回率 |
| 字段抽取 | 字段级 Precision/Recall/F1、关键字段严重遗漏率 |
| 完整度 | 与人工追问决策一致率、无效追问率 |
| RAG | Recall@K、MRR、时效正确率 |
| 报告 | 引用支持率、事实一致性、建议可执行性、严重法律错误率 |
| OCR | CER、关键字段 F1，并按清晰/模糊/倾斜分层 |
| 系统 | P50/P95 延迟、单案 token 与成本、失败率 |

### 5. Bad Case 闭环

```text
发现失败 -> 分类 -> 判断是数据/检索/Prompt/模型/产品交互问题
-> 修改单一变量 -> 全量回归 -> 对比指标与副作用 -> 版本化发布
```

不能只展示一个修好的例子；必须确认没有“改 A 坏 B”。

## 三、项目面试问答

### Q1：为什么不用一个 Prompt 直接生成报告？

**回答框架：**

单次 Prompt 可以作为基线，但法律场景需要知道错误发生在事实理解、信息缺失、检索还是生成。拆分后每一步有明确输入输出，并能针对性降级和评测。不过项目不会以节点数量证明先进性，最终会比较单次调用与分节点方案的质量、延迟和成本。

### Q2：你现在真的做了 Agent 和 RAG 吗？

**准确回答：**

当前已实现的是六步可观测的规则 Mock 工作流和内置知识匹配，用于验证产品流程与数据契约；它不是完整的自治 Agent，也不是向量 RAG。目标架构规划了真实模型 Provider、权威知识检索和引用校验，只有接入并完成评测后才会在简历中写“落地”。

### Q3：如何降低法律幻觉？

**回答框架：**

首先限制模型只能使用检索到的权威片段；其次让输出携带引用 ID，并用程序核对引用是否存在、原文是否支持结论；再通过未知/低置信度策略拒绝过度结论；最后用包含过时法条、无依据问题和 Prompt 注入的测试集评估严重错误率。免责声明不能替代这些技术和产品护栏。

### Q4：信息完整度为什么不能只算非空字段比例？

**回答框架：**

不同字段对结论影响不同，模型也可能通过乱填提高非空率。应先定义核心门槛，例如扣款金额、扣款理由、合同/退租状态；再对辅助字段做权重评分。评测的是“是否应该继续追问”与人工判断的一致性，而不是字段填得越多越好。

### Q5：如何评估一条建议是否可执行？

**回答框架：**

离线可用结构化 rubric 检查是否包含目标、动作、材料、渠道、时限和风险提示，并由法律专业人员抽样复核；在线观察话术复制、步骤勾选、材料补充和结果回填。单纯让另一个模型打分只能作为辅助，不能当最终真值。

### Q6：Prompt 版本需要记录什么？

**回答框架：**

除 Prompt 文本和版本号，还要记录模型供应商、精确模型版本、temperature、结构化输出 schema、知识库版本、Few-shot、发布时间、关联 Bad Case、离线评测结果和回滚版本。否则无法复现一次输出。

### Q7：如何控制延迟和成本？

**回答框架：**

先通过追踪找出最慢和最贵的节点；确定性步骤用规则，小模型做分类抽取，大模型只负责高价值生成；缓存稳定检索结果；只在信息满足门槛时生成完整报告；并为每案设置 token、重试和总耗时预算。成本优化必须在质量护栏内进行。

### Q8：如何处理用户上传的敏感证据？

**回答框架：**

产品层要明确授权和用途，默认最小采集；工程层按用户与案件隔离、私有存储、短时签名访问、传输与静态加密；调用第三方模型前脱敏并披露数据去向；建立保留期限、主动删除、审计和训练退出机制。完整 Prompt/Response 日志也要做字段级脱敏。

## 四、当前禁止用于简历的表述

- “搭建 DeepSeek + FAISS 法律 RAG”。
- “接入 Tesseract 完成合同与聊天 OCR”。
- “通过 Prompt A/B 测试把准确率从 0.78 提升到 0.86”。
- “幻觉率下降 X%”或“用户满意度 X%”。
- “多 Agent 自主规划并调用工具”。

上述内容只有在代码、运行记录和评测结果同时存在后才能改为已完成表述。
