# 2026-08-07 - 前端黄金路径与 API 联调

## 任务目标

- 交付可点击的押金纠纷 Demo 黄金路径：描述 → 创建案件 → 分析 → 查看报告。
- 前端明确标注「演示模式 · 规则 Mock 基线」。
- 验证前后端 API 联调与生产构建。

## 修改前现状

- React 前端仅为占位欢迎页，无业务路由和 API 调用。
- 后端六步 Mock 分析链路已通过 API 手动验证，但前端无法演示。
- `react-router-dom` 已安装未使用。

## 实现过程

1. 重建 backend `.venv`（旧环境绑定失效 Python 路径），确认 SQLite 模式可启动。
2. 创建 API 客户端（`src/api/client.ts`）与 TypeScript 类型定义。
3. 实现三页路由：`/` 首页、`/case/new` 新建案件、`/case/:caseId` 分析报告。
4. 对接 API：`POST /api/v1/users`（演示用户）、`POST /api/cases`、`POST /api/cases/{id}/analysis`、`GET /api/report/{id}`。
5. 分析页展示：风险等级、完整度、报告五段（摘要/风险/依据/证据/行动）、六步 Agent 轨迹。
6. 配置 Vite 开发代理（`/api` → `localhost:8000`）。
7. 运行 `npm run build` 验证 TypeScript 与生产构建。

## 核心逻辑

### 业务逻辑

- 首页区分「已实现 / 演示模式 / 规划中」三类能力状态。
- 新建页提供「填入演示样例」降低演示门槛。
- 报告页展示完整 Agent 轨迹，体现「可解释」而非黑盒。

### 技术逻辑

- 演示用户 ID 缓存于 `localStorage`，避免每次创建新用户。
- 业务 API 使用 `{ code, message, data }` 包装；资源 API（users）直接返回实体。
- 分析接口同步返回完整结果（含 report 和 workflow），无需轮询。

## 面试追问准备

### 产品经理角度

**问题：为什么先做 Mock Demo 而不是直接接大模型？**

**回答要点：** Mock 是确定性基线，可先验证「用户是否愿意走完流程、报告结构是否合理」。真实模型接入后，在同一测试集上与 Mock 对比，才能判断复杂架构是否带来收益。

### AI 产品经理角度

**问题：前端如何体现 Agent 可观测性？**

**回答要点：** 分析页展示六步 workflow 轨迹，每步有 task_type、status、latency 和结构化 output。数据来自后端 `ai_task` 表，不是前端伪造。这验证了「分节点」的价值：出错时可定位到哪一步。
